## Why most of these are worse than they look

A test whose name ends `_is_accepted` / `_is_permissive` / `_is_noop` is
asserting *"this must not raise"*. **That is not an assertion.** If the function
is deleted and its body replaced with `return None`, the test still passes. The
name promises a contract the body never checks.

The sound fix has two parts:

1. **Pin the call actually happened** — `client.get.assert_awaited_once()`. This
   is the load-bearing one: it distinguishes "consulted auth and agreed" from
   "returned early because the code is broken".
2. **Pin the return/post-condition** — `assert await fn(...) is None`.

Doing only (2) is better than nothing and is a one-line change; doing (1) is
what makes the test fail when the behaviour is deleted.

## Known limitation of the detector (read before closing the backlog)

Helper resolution is same-module, and assertions inside a **fixture** are not
credited to the test. A test that delegates every check to a helper in another
file, or that relies on a fixture to assert, will be reported here as vacuous
even though it is not. Every item above was hand-read; the list is accurate, but
it is a lower bound on *reporting*, and it is a complete list of tests whose
**own body** contains no reachable assertion.

Re-run the detector after fixing — the count must go **down**, and
`python scripts/find_vacuous_tests.py --self-test` must stay green. If the count
rises, something has started calling a helper that contains an assertion it did
not use to, and that test should be re-read by hand.
